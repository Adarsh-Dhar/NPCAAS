# Migration Guide: From KITE_API_KEY to x402 Payment Protocol

## Summary

The Nexus OTC codebase has been migrated from the deprecated Kite API key flow (`/v1/payments/authorize`) to the current **x402 Machine Payment Protocol** using `kpass` CLI sessions.

## What Changed

### Removed
- ❌ `KITE_API_KEY` environment variable (no longer needed)
- ❌ Static API key authentication via Bearer token
- ❌ Deprecated `lib/kite-payment.js` module (calls old `/v1/payments/authorize` endpoint)
- ❌ API key references in `.env`, `.env.example`, and agent scripts

### Added
- ✅ New `lib/x402-payment.js` module (x402-compliant payment header generation)
- ✅ Dynamic kpass agent session creation with passkey approval
- ✅ Session-scoped budget and TTL constraints
- ✅ x402 Machine Payment Protocol support on client and server

## How to Run

### Prerequisites
```bash
# Install kpass CLI
npm install -g kpass

# Set your LLM key
export ANTHROPIC_API_KEY=sk-...
```

### Setup
```bash
# Copy environment file
cp .env.example .env

# Edit .env - no KITE_API_KEY needed anymore
# Set: ANTHROPIC_API_KEY, KITE_PAYEE_ADDRESS, KITE_ASSET_ADDRESS
```

### Start Services
```bash
# Terminal 1: Start server
cd nexus-server
npm install
npm run metaverse:js

# Terminal 2: Deploy broker (auto-creates x402 session)
ANTHROPIC_API_KEY=sk-... node .nexus-client/script.js deploy-broker \
  --pool-id POOL-1234 \
  --broker-name DemoBot

# Terminal 3: Start frontend
cd frontend
npm install
npm run dev
```

## Key Differences

| Aspect | Legacy (API Key) | New (x402 + kpass) |
|--------|------------------|-------------------|
| **Authentication** | Static `KITE_API_KEY` env var | Dynamic passkey approval via kpass |
| **Payment Header** | Generated by calling `/v1/payments/authorize` API | Generated by wrapping kpass session data |
| **Session Model** | None (stateless API calls) | Stateful session with budget/TTL |
| **Approval Flow** | Automatic (API key provided) | Interactive (user passkey approval) |
| **Budget Control** | Unbounded per request | Enforced by session | 
| **Module** | `lib/kite-payment.js` | `lib/x402-payment.js` |

## Implementation Details

### Session Creation Flow (`.nexus-client/script.js`)

1. **Register Agent**
   ```javascript
   const regData = parseKpassJSON(
     kpass_register(),
     'agent:register'
   );
   const agentId = regData.agent_id || ...;
   ```

2. **Create Delegation Request**
   ```javascript
   const delegation = JSON.stringify({
     task: { summary: `Autonomous OTC trading: ${brokerName}...` },
     payment_policy: {
       allowed_payment_approaches: ['x402'],  // ← Required
       assets: ['USDC'],
       max_amount_per_tx: '50.00',
       max_total_amount: '500.00',
       ttl_seconds: 3600,
     },
   });
   ```

3. **Create Session** (User approves via passkey)
   ```javascript
   const sessData = parseKpassJSON(
     kpass_sessionCreate(delegation),
     'agent:session create'
   );
   // sessData contains: authorization, signature, session_id
   ```

4. **Pass Session Data to Payment Function**
   ```javascript
   const xPayment = await getSignedXPayment(paymentTerms, sessData);
   ```

### Payment Header Generation (`lib/x402-payment.js`)

```javascript
async function getSignedX402Payment(paymentTerms, sessionData) {
  // Validate session data contains authorization + signature
  if (!sessionData.authorization || !sessionData.signature) {
    throw new Error('Invalid session: missing authorization or signature');
  }

  // Wrap into x402 format
  const x402Payload = {
    authorization: sessionData.authorization,
    signature: sessionData.signature,
    paymentTerms: { /* ... */ },
    timestamp: new Date().toISOString(),
  };

  // Base64-encode for HTTP header
  return Buffer.from(JSON.stringify(x402Payload)).toString('base64');
}
```

### Server Settlement (No Changes)

The server (`nexus-server/src/app.ts`) already handles x402:
- Returns `402 Payment Required` with x402 error schema
- Calls `settleX402Payment()` to verify with Kite Facilitator
- Issues delivery token after settlement

## Environment Variables

### Removed
- `KITE_API_KEY` ❌

### Still Required
- `ANTHROPIC_API_KEY` — LLM provider key
- `KITE_PAYEE_ADDRESS` — Your wallet to receive USDC
- `KITE_ASSET_ADDRESS` — Testnet USDT contract
- `KITE_NETWORK` — `kite-testnet` (default)
- `KITE_FACILITATOR_URL` — Settlement endpoint (default: `https://facilitator.pieverse.io`)
- `NEXUS_PUBLIC_URL` — Public HTTPS merchant URL used in x402 challenges and session scopes
- `NEXUS_PAYMENT` — Must be `x402` (default)
- `NEXUS_SERVER_URL` — Backend URL (default: `http://localhost:5000`)
- `PORT` — Server port (default: `5000`)

### Optional Tuning
- `NEXUS_KPASS_TIMEOUT_MS` — Session creation timeout (default: 300000ms)
- `NEXUS_KPASS_WAIT_TIMEOUT_MS` — Session status wait timeout (default: 1800000ms)
- `NEXUS_MAX_PER_TX` — Max USDC per trade (default: `50.00`)
- `NEXUS_MAX_TOTAL` — Max USDC lifetime (default: `500.00`)

## Troubleshooting

### "kpass binary not found"
```bash
npm install -g kpass
# or set KPASS_BIN=/path/to/kpass in .env
```

### "Session data required for x402 payment"
- Ensure `kpass agent:session create` was called and approved
- Check `allowed_payment_approaches: ['x402']` in delegation
- Verify `NEXUS_PAYMENT=x402` in .env

### "No payment terms in 402 response"
- Server returned 402 but missing `accepts` array
- Check server logs for x402 error details

### Settlement failed: "Invalid authorization"
- Session may have expired (check TTL)
- User revoked session via `kpass agent:session revoke`
- Session budget exceeded
